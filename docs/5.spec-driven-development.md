# 5. SPEC-DRIVEN DEVELOPMENT - 스펙에서 테스트로

스펙 드리븐 개발(Spec-Driven Development)은 구현에 앞서 요구사항을 검증 가능한 인수 조건으로 합의하고, 그 조건을 테스트와 코드에 연결하는 방식입니다. 스펙에는 사용자가 보내는 입력, 응답, 시스템 상태 변화를 기록합니다. 이 예제에서는 BDD의 Given–When–Then으로 조건을 정리하고 TDD의 실패 → 통과 → 리팩터링 순서로 구현합니다.

## 5.1 주문 수량 스펙

상품 단가는 100이고 최초 재고는 5개입니다. 수량은 1 이상의 정수입니다. 주문을 변경할 때는 기존 수량과의 차이만큼만 재고를 증감합니다. 주문과 재고 상태는 별도 조회 요청으로 확인할 수 있어야 합니다.

| ID | Given | When | Then |
| --- | --- | --- | --- |
| ORD-01 | 사용자와 재고 5개인 상품이 있다 | `POST /orders`에 `userId`, `productId`, `quantity`를 보내 1개 또는 5개를 주문한다 | HTTP 200. 주문이 `PENDING`으로 저장된다. 수량과 총액은 각각 1개·100 또는 5개·500이고 남은 재고는 4개 또는 0개다. |
| ORD-02 | 사용자와 재고 5개인 상품이 있다 | 같은 요청으로 0개, -1개 또는 6개를 주문한다 | HTTP 400. 주문이 생성되지 않고 재고는 5개로 유지된다. |
| ORD-03 | `PENDING` 주문 수량이 2개이고 남은 재고가 3개다 | `PUT /orders/{id}/quantity`에 `newQuantity`를 보내 수량을 1개 또는 5개로 바꾼다 | HTTP 200. 주문이 `PENDING`을 유지하고 수량과 총액은 각각 1개·100 또는 5개·500으로 바뀐다. 남은 재고는 4개 또는 0개다. |
| ORD-04 | `PENDING` 주문 수량이 2개이고 총액은 200, 남은 재고는 3개다 | 같은 요청으로 0개, -1개 또는 6개로 바꾼다 | HTTP 400. 주문 상태, 수량, 총액과 재고가 모두 유지된다. |

## 5.2 인수 조건을 테스트에 옮기기

[OrderQuantitySpecification](../src/test/java/io/github/junhkang/springboottesting/specification/OrderQuantitySpecification.java)은 인수 조건 ID를 JUnit 테스트 이름에 넣고 `@ParameterizedTest`로 경계값을 실행합니다. `@SpringBootTest`로 애플리케이션을 구성하고 `MockMvc`로 Spring MVC에 요청을 보냅니다. 실제 저장 결과는 앱의 조회 API에서 확인하며 데이터는 인메모리 H2에 저장됩니다.

같은 시나리오를 [기본 JPA 프로필](../src/test/java/io/github/junhkang/springboottesting/specification/JpaOrderQuantitySpecificationTest.java)과 [MyBatis 프로필](../src/test/java/io/github/junhkang/springboottesting/specification/MyBatisOrderQuantitySpecificationTest.java)에서 각각 실행합니다.

```bash
./mvnw "-Dtest=*OrderQuantitySpecificationTest" test
```

## 5.3 실패를 확인하고 구현하기

1. `ORD-02`와 `ORD-04`를 실행합니다. 수량 검증을 추가하기 전에는 두 구현 모두 0과 음수에 HTTP 200을 반환했습니다. 음수로 주문하면 주문 수량을 재고에서 빼는 계산 때문에 재고가 오히려 늘었습니다.
2. 주문 생성과 수량 변경에서 공통 수량 검증을 호출합니다. [Order.validateQuantity](../src/main/java/io/github/junhkang/springboottesting/domain/Order.java)가 `IllegalArgumentException`을 던지면 [GlobalExceptionHandler](../src/main/java/io/github/junhkang/springboottesting/exception/GlobalExceptionHandler.java)가 HTTP 400으로 응답합니다.
3. 인수 테스트와 전체 테스트를 다시 실행합니다. 재고를 모두 쓰는 주문과 수량을 줄이는 변경도 계속 성공해야 합니다. 요구사항이 바뀌면 스펙 표와 해당 ID의 테스트를 같은 PR에서 갱신합니다.
