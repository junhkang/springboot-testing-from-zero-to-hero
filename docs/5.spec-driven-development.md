# 5. SPEC-DRIVEN DEVELOPMENT - 스펙에서 테스트로

스펙 드리븐 개발(Spec-Driven Development)은 구현 전에 요청, 응답, 상태 변화를 검증 가능한 인수 조건으로 정하고, 각 조건을 테스트에 연결하는 방식입니다. 주문 수량 예제에서는 HTTP 응답과 저장된 상태를 함께 확인합니다.

## 5.1 주문 수량 스펙

상품 단가는 100이고 최초 재고는 5개입니다. 수량은 1 이상의 정수입니다. 주문을 변경할 때는 기존 수량과의 차이만큼 재고를 조정합니다. 생성과 변경 요청의 입력은 [주문 컨트롤러](../src/main/java/io/github/junhkang/springboottesting/controller/OrderController.java)에서 요청 파라미터로 받습니다.

| ID | Given | When | Then |
| --- | --- | --- | --- |
| ORD-01 | 사용자와 재고 5개인 상품이 있다 | `POST /orders`에 `userId`, `productId`, `quantity`를 보내 1개 또는 5개를 주문한다 | HTTP 200. 주문이 `PENDING`으로 저장된다. 수량과 총액은 각각 1개·100 또는 5개·500이고 남은 재고는 4개 또는 0개다. |
| ORD-02 | 사용자와 재고 5개인 상품이 있다 | 같은 요청으로 0개, -1개 또는 6개를 주문한다 | HTTP 400. 주문이 생성되지 않고 재고는 5개로 유지된다. |
| ORD-03 | `PENDING` 주문 수량이 2개이고 남은 재고가 3개다 | `PUT /orders/{id}/quantity`에 `newQuantity`를 보내 수량을 1개 또는 5개로 바꾼다 | HTTP 200. 주문이 `PENDING`을 유지하고 수량과 총액은 각각 1개·100 또는 5개·500으로 바뀐다. 남은 재고는 4개 또는 0개다. |
| ORD-04 | `PENDING` 주문 수량이 2개이고 총액은 200, 남은 재고는 3개다 | 같은 요청으로 0개, -1개 또는 6개로 바꾼다 | HTTP 400. 주문 상태, 수량, 총액과 재고가 모두 유지된다. |

## 5.2 인수 조건을 테스트에 옮기기

[OrderQuantitySpecification](../src/test/java/io/github/junhkang/springboottesting/specification/OrderQuantitySpecification.java)은 인수 조건 ID를 JUnit 테스트 이름에 넣고 `@ParameterizedTest`로 여러 수량을 실행합니다. 예를 들어 ORD-04는 수량을 변경하려는 시도가 거절된 뒤 주문과 재고를 다시 조회합니다.

```java
@ParameterizedTest(name = "ORD-04 수량 변경 거부 수량 {0}")
@ValueSource(ints = {0, -1, 6})
void rejectsInvalidUpdateWithoutChangingOrderOrStock(int newQuantity) throws Exception {
    long orderId = createPendingOrder(2);

    updateQuantity(orderId, newQuantity).andExpect(status().isBadRequest());

    expectStoredOrder(orderId, 2, 200.0);
    expectStock(3);
}
```

`expectStoredOrder`는 `GET /orders/{id}`로 상태·수량·총액을, `expectStock`은 `GET /products/{id}`로 남은 재고를 확인합니다. `@SpringBootTest`와 `MockMvc`로 실제 서비스와 H2를 연결하고, 같은 10개 사례를 [기본 JPA 프로필](../src/test/java/io/github/junhkang/springboottesting/specification/JpaOrderQuantitySpecificationTest.java)과 [MyBatis 프로필](../src/test/java/io/github/junhkang/springboottesting/specification/MyBatisOrderQuantitySpecificationTest.java)에서 각각 실행합니다.

```bash
./mvnw "-Dtest=*OrderQuantitySpecificationTest" test
```

Windows에서는 [빠른 시작의 PowerShell 명령](../README.md#빠른-시작)을 사용합니다.

## 5.3 실패를 확인하고 구현하기

1. **실패 재현** — 수량 하한 검증을 추가하기 전에는 `ORD-02`와 `ORD-04`에서 0과 음수를 보내면 HTTP 200이 돌아왔습니다. 음수로 주문하면 재고에서 음수를 빼면서 재고가 오히려 늘었습니다.
2. **구현** — 주문 생성과 수량 변경에서 공통 검증을 호출합니다. [Order.validateQuantity](../src/main/java/io/github/junhkang/springboottesting/domain/Order.java)가 `IllegalArgumentException`을 던지면 [GlobalExceptionHandler](../src/main/java/io/github/junhkang/springboottesting/exception/GlobalExceptionHandler.java)가 HTTP 400으로 응답합니다.
3. **회귀 검증** — 인수 테스트와 전체 테스트를 실행해 잘못된 요청을 거절하는지, 재고를 모두 쓰는 주문과 수량을 줄이는 변경은 성공하는지 확인합니다. 요구사항이 바뀌면 스펙 표와 해당 ID의 테스트를 같은 PR에서 갱신합니다.
